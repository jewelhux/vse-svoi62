# Техническое задание: одностраничный сайт автосервиса

## 1) Общая информация

### 1.1. Назначение проекта
- Разработать одностраничный сайт-визитку автосервиса для привлечения клиентов и быстрого перехода к связи.
- Базироваться на текущем сайте [vsesvoy62.ru](https://vsesvoy62.ru/) по структуре и визуальному характеру.
- Подготовить проект к будущему расширению (подключение backend, углубление SEO, добавление новых страниц).

### 1.2. Формат запуска
- Этап 1 (текущий): одна страница, без backend.
- Основной пользовательский сценарий: просмотр информации -> переход в Telegram / звонок.

### 1.3. Контакты и каналы связи
- WhatsApp не используется.
- Основной мессенджер: Telegram.
- Контактный номер для коммуникации: `+7 961 130 6949`.

---

## 2) Технический стек и архитектурные требования

### 2.1. Технологии
- `Next.js` (App Router).
- `React`.
- `TypeScript`.
- `Chakra UI` со сбросом браузерных стилей (`preflight/reset`).
- `@tanstack/react-query` для слоя запросов и кеширования.
- `zustand` для локального UI-state.

### 2.2. Архитектурные принципы
- Компонентный подход: переиспользуемые секции, карточки, кнопки, типографика и контейнеры.
- Четкое разделение:
  - UI-компоненты (презентационные),
  - слой данных (Query hooks/адаптеры),
  - локальный state (Zustand).
- Даже без backend на текущем этапе заложить API-слой с заглушками, чтобы подключение реальных endpoint прошло без переработки структуры.

### 2.3. Готовность к масштабированию
- Выделить конфиг-контент (данные секций/контакты/faq) в удобные структуры.
- Подготовить типы доменных сущностей (услуга, отзыв, кейс, FAQ, контакт).
- Заложить возможность добавления новых страниц без рефактора базового layout.

---

## 3) Цели и KPI первой версии

### 3.1. Бизнес-цели
- Повысить количество обращений в сервис.
- Упростить путь клиента до контакта.
- Сформировать доверие через прозрачную подачу услуг, преимуществ и отзывов.

### 3.2. Продуктовые KPI (MVP)
- Не более 2-3 кликов до действия связи.
- Явные CTA в первом экране и внизу страницы.
- Корректная работа на мобильных устройствах.

---

## 4) Структура страницы (MVP)

Все блоки ниже обязательны, кроме помеченных как "рекомендованный". Если у блока нет контента, блок не выводится.

### 4.1. Header
- Логотип (использовать с текущего сайта).
- Навигация по якорям страницы.
- Кнопки связи: Telegram, телефон.
- На мобильных: бургер/компактная навигация.

### 4.2. Hero (первый экран)
- УТП автосервиса.
- Краткие преимущества в 2-4 пунктах.
- Основные CTA:
  - "Написать в Telegram",
  - "Позвонить".
- Доп. визуал: тематичное фото в едином стиле с остальными блоками.

### 4.3. Блок преимуществ
- 4-6 карточек преимуществ (например: гарантия, честная смета, скорость, опыт).
- Краткий и понятный копирайтинг без перегруза.

### 4.4. Блок услуг
- Список услуг, аналогичный текущему сайту:
  - малярные работы,
  - кузовные работы,
  - обработка кузова,
  - слесарные работы,
  - полировка,
  - тюнинг/обвесы.
- Каждая карточка: название, короткое описание, CTA "Запросить расчет" (ведет в Telegram).

### 4.5. О компании
- Короткий блок про сервис: опыт, подход, гарантии, прозрачность.

### 4.6. Наши работы / портфолио
- Галерея кейсов (до/после или просто работы).
- Допустима начальная версия в формате 4-8 изображений.

### 4.7. Отзывы
- Список отзывов с именем клиента и кратким текстом.
- При наличии источника возможно добавить отметку "Яндекс Карты" (текстом/иконкой).

### 4.8. FAQ
- Аккордеон с частыми вопросами.
- Ключевые темы: виды работ, детали, сроки, гарантия, расчет стоимости.

### 4.9. Контакты (обязательный блок)
- Телефон, Telegram, адрес.
- Режим работы.
- Встроенная карта (Яндекс или Google).
- CTA-кнопки связи.

### 4.10. Footer
- Краткая служебная информация.
- Копирайт.

## 5) Дополнительные рекомендованные блоки (уместные для тематики)

  - "Telegram",

### 5.3. Блок "Как быстро оценить стоимость" (рекомендованный)
- Короткий инфо-блок с объяснением сценария обращения в Telegram.

## 6) UI/UX требования

### 6.1. Визуальный стиль
- Ориентир на стилистику текущего сайта [vsesvoy62.ru](https://vsesvoy62.ru/): общий характер, тональность, простота восприятия.
- Не делать копию 1:1: сохранить узнаваемость, но улучшить чистоту верстки и современность интерфейса.

### 6.2. Изображения
- Использовать фото из открытых источников/стоков.
- Все изображения должны быть в едином стиле (цветокор, ракурсы, общий mood).
- Избегать визуально конфликтующих изображений.

### 6.3. Адаптивность
- Mobile-first.
- Обязательные брейкпоинты:
  - мобильная версия,
  - планшетная версия,
  - desktop.
- Проверить читаемость текста, кликабельные зоны и доступность CTA на всех размерах.

### 6.4. Доступность (базовая)
- Контрастность текста/кнопок не ниже базовых рекомендаций.
- У всех информативных изображений есть `alt`.
- Управляемость интерактивных элементов с клавиатуры.

## 7) SEO (базовый уровень на этапе MVP)

### 7.1. Обязательно реализовать
- Уникальные `title` и `description` для страницы.
- Open Graph и Twitter meta.
- `robots.txt`.
- `sitemap.xml` (минимальный для 1 страницы).
- ЧПУ URL для главной страницы.

### 7.2. Подготовка к расширению SEO
- Централизованный SEO-конфиг (чтобы позже легко масштабировать на новые страницы).
- Семантическая HTML-структура (header/main/section/footer).

---

## 8) Интеграции и поведение без backend

### 8.1. Текущая реализация
- Формы отправки данных на сервер не обязательны.
- Основной канал лидогенерации: Telegram-ссылка + телефон.

### 8.2. Подготовка к будущему backend
- Оставить слой API-заглушек/сервисов (на случай появления endpoint для заявок, контента, отзывов).
- Использовать TanStack Query для потенциально удаленных данных даже с локальным mock-источником.

---

## 9) Требования к коду и компонентам

### 9.1. Переиспользуемость
- Все секции реализовать как переиспользуемые компоненты.
- Общие элементы (кнопки, карточки, заголовки секций, контейнеры) вынести в shared-слой.

### 9.2. Состояние
- Zustand использовать для UI-состояний (например, мобильное меню, служебные переключатели интерфейса).
- Не хранить "серверный" кеш в Zustand (для этого TanStack Query).

### 9.3. Типизация
- Полная типизация данных секций и props компонентов.
- Избегать `any`.

### 10.1. Тексты

- Телефон `+7 961 130 6949`.
